# templ-2 · 写笔记（替代 "帮我总结一下"）

## 背景

**烂 prompt 长什么样**：

> "帮我总结一下这篇 paper / 这个实验"

**输出会是**：泛而无重点的几段话，没结构、没结论、没"用途"意识。**3 个月后你打开自己的笔记，看不懂**。

**好 prompt 应该做的**：先确定**"谁读 / 用途 / 核心结论"** 三件事，再动手——这就是 spec-driven 写作。

> 关键洞察：**"3 个月后的自己" 才是笔记的真正读者**。
> spec-driven 让你**替未来的自己**把上下文先写进去。

## Prompt 模板

```
我想就 [topic / paper / 实验] 写一份笔记。先不要动手。

先一问一答帮我把以下 5 件事确定下来：
1. 这份笔记将来谁会读？（自己 3 个月后？合作者？导师？）
2. 笔记的用途：备忘 / 引用源 / 综述素材 / 复现 SOP？
3. 我想沉淀的核心结论（不是知识点，是结论——一句话陈述）
4. 笔记结构草稿（标题 + 一级小标题）
5. 需要外部引用 / 数据 / 图的位置（先列 placeholder）

确定后再 /writing-plans，再写。
```

## 使用流程（3 步）

### Step 1：Brainstorming（不动手，只问）

把上面的 prompt 发给 Agent。它应该开始**逐个问你 5 件事**，而不是直接写笔记。

**关键质量信号**：
- ✅ 第 1 问"将来谁读"——这一问能逼出文风差异
- ✅ 第 3 问"核心结论"时如果你说不出来，**就该停下来想想——也许这件事还没准备好写笔记**

### Step 2：Writing Plan

完成 brainstorming 后，发：

```
按上面 spec，用 /writing-plans 流程帮我把笔记拆成可执行计划。
每节大概 200-400 字，列出每节核心论点 + 用到的证据。
```

### Step 3：分节写

```
现在按 plan 写第 1 节。
请引用真实出处（不要编造），按 MEMORY.md 里的 writing_style 偏好写。
```

写完一节，起 sub-agent reviewer（见下面"进阶"）。

## 进阶：sub-agent reviewer

写完整篇笔记后，起一个独立 sub-agent 审稿，复用以下 prompt：

```
你是一个批判性的审稿人。审查这份笔记，找：
1. 过度泛化（"显而易见"、"我们都知道"、"对吧"等空词）
2. 缺引用的事实陈述
3. 语气不一致（正式段和非正式段混在一起）
4. "知识点堆砌" 而没有"我从这件事得出 X" 的句子
5. 真正的读者（你 3 个月后的自己 / 合作者）会卡在哪里

输出：
- 严重问题（必改）：3-5 条
- 改进建议（可选）：3-5 条
- 整体评分（1-10）
```

## 故障排查

| 输出问题 | 修法 |
|---|---|
| Agent 直接开始写笔记不问 | 你的 prompt 不够强；明确说 "**先不要动手**" 加粗 |
| Brainstorming 阶段问题太敷衍 | 让它"挑战我的假设"——例如 "你怎么知道这个结论是 useful 的？" |
| 笔记仍然泛而空 | 第 3 步加 "禁止使用：'其实'、'显而易见'、'我们都知道'、'对吧'——任何假设读者已懂的词" |
| 引用编造（fake citations） | 强制要求 "每条引用必须给可点的链接（arxiv URL 或 doi）"；编造的会被你抓出来 |

## 一些口诀

- **不写空话**：每段必须有"具体数字"或"具体名字"
- **不堆知识点**：每节末尾必须有一句"所以这意味着 X"
- **写给未来的自己**：在心里假设 3 个月后的你是个完全不懂这篇 paper 的人
